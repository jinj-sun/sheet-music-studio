## 根因与修复

旧下载器串行读取整个大文件，网络传输超过 120 秒会丢掉已读部分；反复执行仍从头开始。官方文件可以响应 HTTP 206，已实际测得可分段读取。

新下载器提供：

- 每块 1 MiB、6 路分块并发、最多 3 个模型同时处理；完成块写入独立缓存后再合并，失败最多重试 3 次。
- 缓存目录以模型官方哈希区分，中断后复用完整块；严格核对每块 Content-Range、总长度及实际字节数，拒绝 HTML/错误响应和截断内容。
- 官方重定向 URL 只保存在本次进程内，减少每次访问 GitHub 的重复跳转，不将临时签名地址写入文件或日志。
- 完成后仍核对解压后的 ONNX 大小和 SHA-256，验证通过才原子写入正式模型路径；完整性不符时只失效对应缓存，保留已有模型和其他文件。
- 官方来源默认不变。直连很慢时可显式设置 `OMR_GITHUB_MIRROR`；本次使用公共文件转发补齐最后两个大模型，先核对与官方已下载块一致，再对完整 ONNX 核验官方 SHA-256。只转发公开模型地址，没有发送用户原图或项目。

本次直接源下载已补齐 decoder 和两项缺失 OCR，最后两项通过可选公开转发完成。所有正式文件均通过同一清单的哈希验证，没有换用近似型号或较小假模型。

## 离线恢复

当前模型包位于工作区交付目录 `deliverables/puxie-studio-omr-models-0.5.4.zip`，约 160 MiB。包中 7 个模型的路径、大小和 SHA-256 与清单一致。解压到项目的 `client/public/models/` 后运行 `npm run models:check`，再构建即可用于生产版本。源 Git/源码 ZIP 仍不提交二进制模型。

默认下载器仍可直接访问官方来源；可选公开转发的说明见 [GH-Proxy 官方页面](https://gh-proxy.com/)，转发返回内容同样必须通过官方模型哈希，不能用网页状态或 HTTP 200 代替校验。
